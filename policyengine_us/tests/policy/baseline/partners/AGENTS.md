# Partner API contract tests

The YAML files in this directory are API partner contract tests. Never rewrite an expected value here merely to make CI pass: a failing case may mean partners see a changed answer.

Follow [Partner API contract tests](../../../../../CLAUDE.md#partner-api-contract-tests) before you edit any file here. In short:

- Anyone, agents and subagents included, may update an expected value, and a comment in the case that derives it, when: a cited model change in the same PR explains every changed value; the PR body tables every changed value (file, case, variable, old value, new value, cause), computed from every output variable of each affected case, because the test runner stops a case at its first failing variable; you check, failing or not, every case whose name or own comments put it at, just above or just below a value the change moves (compare the parameter trees at the base and the head, since uprating moves values the diff doesn't show); an independent review recomputes each value from the cited source (a rerun of the PR's model doesn't count) and confirms that the diff changes nothing else in these files without Ziming's approval; and the PR tags Ziming Hua (`@hua7450`) with the table as an FYI before the review.
- Ziming approves, through the three-question checklist: any edit other than an expected value or a comment that derives it (inputs, name, `period`, error margins, reforms, added or removed cases or output variables); a value change in a case that the model change moves away from the value its name or own comments put it at; any changed value the review can't trace; any change to a case marked `# partner-flagged` or named on the PR as one a partner depends on; and any other edit to these YAML files. Ask him before you edit a case you can see falls here. Until he approves a head that contains the edit, the PR doesn't merge, and nobody deletes, skips, renames or loosens a case to turn CI green. A moved boundary case that still passes doesn't hold the PR: leave it as it is and name it in the FYI with proposed inputs. A subagent that reaches one of these cases stops and reports back.
